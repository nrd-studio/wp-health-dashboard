# 🩺 WP Health Dashboard

WordPress サイトの健康状態を外部からチェックし、安全に更新するためのメンテナンスダッシュボードです。

**「昔納品したサイトが、いつの間にか WordPress 7.0 に勝手に上がっていた」** —— そんな事故を防ぐために作られています。

![License](https://img.shields.io/badge/license-MIT-blue)

## できること

- **バージョン監視** — WordPress 本体 / PHP / 全プラグインの現在・最新バージョンを一覧表示し、健康スコアで評価
- **🛡 自動更新ポリシーの検知と制御** — メジャーバージョン自動更新が ON になっているサイトを発見し、ワンクリックで OFF に（セキュリティ修正のマイナー自動更新は維持されます）
- **⚠ 意図しない更新の検知** — 前回スキャン時から WordPress のバージョンが変わっていたら警告
- **更新前リスク分析** — テーマの PHP ファイルを静的解析し、プラグイン依存箇所や PHP 8.x 非互換パターンを検出してから更新
- **遠隔更新** — 分析結果を確認した上で、ダッシュボードから本体・プラグインを更新

## 仕組み

```
┌─────────────────────────┐         ┌──────────────────────────┐
│  ダッシュボード (Vercel)  │  REST   │  WordPress サイト         │
│  index.html             │ ──────▶ │  wp-health-agent.php     │
│  api/proxy.js           │  API    │  (プラグイン)             │
└─────────────────────────┘         └──────────────────────────┘
```

ダッシュボードは Vercel にデプロイし、監視したい各 WordPress サイトにはエージェントプラグインを 1 ファイル設置します。通信は API キー（`X-WPH-Key` ヘッダ）で認証されます。

## セットアップ

### 1. ダッシュボードのデプロイ（最初に 1 回）

このリポジトリを fork または clone し、Vercel にインポートしてデプロイします。設定は不要で、`index.html` と `api/proxy.js` がそのまま動きます。

### 2. WordPress サイト側（監視したいサイトごと）

1. `wp-health-agent.php` を `wp-content/plugins/` にアップロードし、管理画面で有効化
2. **設定 → WP Health Agent** で API キーを生成してコピー
3. ダッシュボードを開き、サイト URL と API キーを入力 → スキャン開始

> **サイト URL の注意**: `https://` 必須です。また `www` の有無を含めた正規 URL を入力してください（リダイレクトは安全のため追跡しません）。

## 使い方

### 自動更新ポリシーバーの見方

スキャン後、スコアの下に表示されます。

| 表示 | 意味 |
|---|---|
| メジャー: OFF ✓ | 7.0 等への自動更新は走りません（安全） |
| メジャー: ON ⚠ | メジャーバージョンに勝手に上がる可能性あり → ボタンで OFF に |
| ボタンがグレー | `wp-config.php` の `WP_AUTO_UPDATE_CORE` 定数で固定されており、サーバー上での編集が必要 |
| 自動更新システム全体が無効 | セキュリティ修正も自動適用されないため、手動での追従が必要 |

バー右端には設定の出どころ（管理画面の設定 / wp-config.php の定数 / WordPress デフォルト / フィルター上書き）が表示されます。

### 推奨運用

1. **初回**: 全サイトをスキャンし、メジャー自動更新が ON のサイトを OFF にする
2. **定期（月 1 程度）**: 同じブラウザでスキャンし、バージョン変化バナーと更新待ちを確認
3. **メジャーアップデート時**: プラグインを先に最新化 → バックアップ → 本体を手動更新

## セキュリティ

- API キーは `X-WPH-Key` ヘッダで送信されます（URL に載らないためアクセスログに残りません）
- プロキシは SSRF 対策済み: https 限定・プライベート IP 帯の遮断・パスのホワイトリスト検証・リダイレクト不追跡
- エージェントプラグインの認証は `hash_equals()` によるタイミング攻撃耐性のある比較です
- API キーが漏れた場合は、設定ページの「API キーを再生成」で即座に無効化できます

## 制限事項（正直な話）

- **ホスティング会社による独自の自動更新**（サーバーパネルの「WordPress 自動更新」機能など）は WordPress の外側で動作するため、このツールでは検知も制御もできません。該当機能のあるサーバーでは、パネル側の設定もあわせて確認してください。
- バージョン変化の検知はブラウザの localStorage に依存します。別のブラウザ・端末から開いた場合は前回比較ができません。
- テーマの静的解析は既知パターンのマッチングであり、実行時エラーをすべて検出できるわけではありません。重要な更新の前にはテスト環境での確認を推奨します。

## 動作要件

| 項目 | 要件 |
|---|---|
| WordPress | 5.6 以上 |
| PHP | 7.4 以上（エージェントプラグイン） |
| ダッシュボード | Vercel（Node.js 18 以上のサーバーレス関数） |

## エンドポイント一覧（エージェントプラグイン）

| Method | パス | 説明 |
|---|---|---|
| GET | `/wp-json/wp-health/v1/status` | バージョン・更新情報の取得 |
| GET | `/wp-json/wp-health/v1/theme-files` | テーマ PHP の取得(リスク分析用) |
| GET | `/wp-json/wp-health/v1/auto-update` | 自動更新ポリシーの取得 |
| POST | `/wp-json/wp-health/v1/auto-update/major` | メジャー自動更新の ON/OFF |
| POST | `/wp-json/wp-health/v1/update/core` | WordPress 本体を更新 |
| POST | `/wp-json/wp-health/v1/update/plugin` | プラグインを更新(body: slug) |
| POST | `/wp-json/wp-health/v1/update/all` | すべてを一括更新 |
